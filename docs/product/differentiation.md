# Differentiation

## The hard question

> 「InstagramやPinterestで良くないですか？」

## Short answer

Instagram / Pinterestは「見つけて保存する」ことに強い。New Communityは、そのInspirationをNITORIの商品・価格・Room条件・既存家具・Store Actionに接続し、実行可能なPLANへ変換することを目的にする。

## Comparison

| Capability | Instagram / Pinterest | Current NITORI public assets | Proposed Community |
|---|---|---|---|
| Visual inspiration | Strong | Strong: Staff / User / Seasonal | 既存Assetを活かす |
| Social reach | Strong | Instagram original postへの接続 | MVPでは競わない |
| Product / SKU structure | Link / tag依存 | 使用ItemとNITORI SKUを接続 | Coordinateの必須構造として役割も保持 |
| Room condition | Caption依存 | 一部Room / housing / tagあり | Normalized room size / housing / household |
| Problem / need | Search text依存 | Seasonal / tagで一部あり | Structured need filter |
| Budget / total | 手計算 | 個別価格、Staff detailに使用Item | Plan total / budget fit |
| Existing furniture | Caption依存 | Adviserで条件付き相談 | Existing / TO_BUY roleをPlanに保持 |
| Product replacement | Copyして手作業 | Simulation / adviserで部分対応 | Why / before / afterを残すlimited adaptation |
| Product→Coordinate | 非構造的 | Staff Coordinateで一部成立 | Room / need条件で横断 |
| PLAN→REAL | Native domainではない | 公開監査で共通状態未確認 | First-class lifecycle |
| Store / EC action | 外部link | NITORI EC / App / floor mapが強い | Official destinationへのhandoff |
| Multi-product route | なし | Room Harmony prototypeにあり | Room Harmonyへhandoff |
| Trust / provenance | Account / platform label | Staff / User sourceあり | REAL / PLAN、Official / Staff / User、AI provenance |

## NITORI-specific moat hypothesis

次の組合せがNITORIだから成立する可能性がある。

1. Official product identity and availability boundary
2. CoordinateとSKUの構造接続
3. Room context / Need / Budget / Existing furniture
4. EC / Store / Adviser asset
5. Room Harmony recommendation and route
6. PLAN→REAL→next PLAN lineage

単体では他社も模倣可能だが、一つのUser stateとして接続されると「画像保存」より実行に近づく。

## Why this is not an Instagram clone

- Feed itemは`Post`ではなく`Coordinate`。
- SuccessはLikeやfollowerではなく、条件一致、multi-product exploration、PLAN、Store / EC action。
- Remixは画像Copyではなく、budget / room / need / product replacementの差分。
- Social graphよりProduct graph・Room context・derivation graphを優先。
- Commerce、Inventory、Routeは既存NITORI systemへ渡し、Community内で偽の在庫やMapを持たない。

## Why users may still choose Instagram / Pinterest

**RISK**: Visual variety、Creator reach、Trend speedは既存social platformが圧倒的に強い。New Communityが画像Feedだけなら利用理由はない。

成立条件:

- 2〜3操作で自分の条件に近い事例へ到達できる。
- Product ID、価格、Total、Store actionが正確である。
- 「このCoordinateを自分向けに変更」が実際にPlanを短縮する。
- Existing NITORI account / App / Storeへの遷移が途切れない。

## Relationship with ChatGPT / general AI

General AIは自然言語相談・アイデア生成に強い。一方、このProductの価値仮説は「NITORI商品・Coordinate・店舗・価格等の承認済みDataを真実源として、実行可能な状態を保つ」ことである。

ただし「社内Dataだから必ず正確」とは言えない。更新頻度、在庫時刻、店舗差、説明責任が必要であり、LLMを使う場合もProduct / price / stockはAPI truthから取得する。

## Defensible one-liner

> Pinterestで「好き」を見つけ、NITORI Communityで「自分の部屋で実現できるPLAN」に変え、NITORI EC・店舗・Room Harmonyで確かめる。

## Claims discipline

- **VERIFIED FACT**: Current NITORIはCoordinateとSKU / EC / Storeを既に部分接続している。
- **INFERENCE**: Structured PLANとlifecycleは既存Assetを補完する合理的なGapである。
- **HYPOTHESIS**: この差別化が利用・multi-product exploration・併売率を高める。ResearchとExperimentが必要。
